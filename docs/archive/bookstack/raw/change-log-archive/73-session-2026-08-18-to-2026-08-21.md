## Kern HQ — Home Assistant

HA Container 2026.8.2 with a **fully local** voice pipeline: on-device wake word →
Speech-to-Phrase → `conversation.home_assistant` (no LLM) → Piper. Voice PE puck adopted at
`10.0.0.71`. Verified end to end.

Two BookStack "open decisions" closed: container-on-host (not HAOS/appliance), and fully local
voice (no Nabu Casa).

**Speech-to-Phrase only knows entities exposed to Assist.** An unexposed device returns an
**empty transcript with no error**. Retrain with `docker compose restart speech-to-phrase`.

### Amazon plug bridge

`input_boolean.bookshelf_lights` is the voice target. The chime came from
`alexa_devices.send_text_command`, which feeds an utterance to the Echo's speech engine.

**Key discovery:** `alexa_devices` exposes every enabled Alexa routine as an HA **button**, and
pressing it calls `call_routine()` → `AmazonSequenceType.Routines`, which runs the routine
directly and is **silent**. So HA pushes to Alexa; Alexa never needs to watch HA. No Nabu Casa,
no HA→Alexa exposure.

**Outstanding:** two Alexa routines must be created by hand (`Bookshelf Lights ON` / `OFF`,
Smart Home → plug → power, **no speech action**, enabled). Then repoint the automation to
`button.press` and delete the legacy bridge.

### Voice PE button

Double-press the dial toggles bookshelf + Govee + TP-Link as a group. **Single press is not
available** — the firmware consumes it for the assistant and never emits it. Only
`double_press`, `triple_press`, `long_press`, `easter_egg_press` exist. `govee_light_local` is
fire-and-forget UDP and drops commands (1 in 7 observed), so the automation re-asserts it.

## Komga — 100% CPU bug

"Jellyfin CPU is high" was **not Jellyfin** (0.01%, no ffmpeg). Komga had a core pegged for
3h40m.

`ReadListLifecycle.getThumbnailBytes` has `while (size < 4) { this += bookIds.take(4) }`. With an
**empty read list**, nothing is appended and the loop never exits. **All 8 read lists are
empty.** Restart clears it; it will recur until the lists are populated or deleted.

Technique worth reusing: `docker kill -s QUIT <container>` dumps JVM thread stacks to the log
**without killing the container** (verify PID 1 is `java` first). `ps` %CPU is a lifetime
average and badly understates recent spikes — use `docker stats`.

## Shelfarr

Requests weren't progressing. Root cause: **Shelfarr memoizes its HTTP connections**, so any
setting typed into the UI after boot is silently ignored until restart. Prowlarr was never
actually misconfigured. Separately, **Hardcover needs the token stored *with* the `Bearer `
prefix** — Shelfarr sends it raw and gets HTTP 400.

**Rule: any Shelfarr settings change requires `docker compose restart shelfarr`.**

Output staging was trialled and **deliberately reverted** — `auto_select_enabled=false` already
forces a human to pick each release, making staging a second review of an already-reviewed
choice. Rationale recorded in the compose file; do not re-add without asking.

## SSD migration — stack-wide

Docker's data root is `/mnt/avrana_media/docker`, the **7.3 TB spinning array**. Measured fsync
**775 ms (sdb) vs 1.33 ms (sda)** — ~580×. Every session write in Tracearr died with PostgreSQL
`57014 "canceling statement due to statement timeout"`.

The trigger was SABnzbd unpacking ~20 GB: `unrar` jammed the array's ext4 journal, leaving
`jbd2/sdb1-8` and Postgres' checkpointer in D-state. The container needed SIGKILL.

**Migrated to the SSD:** Tracearr (466 MB) and Authentik's Postgres (115 MB, `pg_dump` taken
first). Result: Tracearr boots in **10 s** instead of 1–3 min, zero crashes, zero timeouts.

**Checked, not assumed:** BookStack, Komga and Shelfarr were *already* on the SSD via bind
mounts under `/home/cody`. Only Authentik and Tracearr were affected. Docker **images**
(19.9 GB) stay on the array — read-mostly, no benefit to moving.

**Outstanding:** ~58 GB of SSD is unallocated. `sudo lvextend -l +100%FREE
/dev/ubuntu-vg/ubuntu-lv && sudo resize2fs /dev/ubuntu-vg/ubuntu-lv` takes root 57 GB → ~116 GB,
online.

## avrana.net portal restructure

The three request services are now nested under one **Request** tile. Previously **only Seerr
was on the portal at all** — `requestabook` and `requestacomic` were not exposed anywhere.

Permissions now track the library each service feeds:

| Service | Gate |
|---|---|
| Movies & TV (Seerr) | `avrana-videos` |
| Books (Shelfarr) | `avrana-books` **OR** `avrana-audiobooks` |
| Comics (Omnibus) | `avrana-comics` |

Service group slots now accept a tuple as well as a string, applied at **all four** permission
checkpoints including route enforcement — hiding a tile is not the only protection. Verified
before applying that `avrana-requests` and `avrana-videos` had identical membership, so nobody
lost access. **`avrana-requests` is now unused** but retained.

Tiles no longer print the hostname. The interstitial still does, deliberately — it tells you
where you are about to be sent.

**Gotcha:** `ALIASES` resolve *before* the chooser lookup, so `{"request": "requests"}` made
`/request` 307 to Seerr and the chooser unreachable. Removed. Seerr keeps `/requests`.

## Portal copy — information leak fixed

The Request chooser originally read *"Movies, books & comics"*. Chooser subtitles are **static**
while tile visibility is **per-group**, so a comics-only user was told a movies service exists —
contradicting the portal's own rule that *"a user with fewer services just sees a smaller grid:
no hint anything is hidden."* It was also inaccurate, since Seerr covers TV as well as film.

Now **"Ask for something that's missing"** — names no media type, so it cannot leak for any group
combination. Verified zero movie/TV mentions on the home grid for comics-only and books-only
users.

Two house rules recorded from this: **no first person** in user-facing copy, and **never name a
service the viewer may not reach**. The `Read` chooser's "Comics & ebooks" is the same pattern
but is explicitly **not** treated as a leak — comics and ebooks always share an access level.
Do not "fix" it.

## Mylar series followed in Omnibus

All **98** of Mylar's tracked series that Omnibus knows about are now followed by Cody, with
**nothing set to auto-download**.

Matched by **ComicVine ID** (`mylar.comics.ComicID` = `omnibus.Series.cvId`), not by title —
essential when two distinct series are both called "Batman" (cv48729 and cv91273).

Following and acquisition are separate concerns in Omnibus: `SeriesFollow` is a per-user
subscription, `Series.monitored` is the auto-download flag. Only the former was touched;
`monitored=TRUE` stayed at 1 and the Request count stayed at 10.

This only worked because the read-only Mylar library had already been scanned (102 Series,
1,763 Issues). Doing it beforehand would have meant fabricating ~98 half-formed Series rows.

**11 Mylar series have no Omnibus record** and so were not followed — Mylar tracks them but has
no files on disk: Absolute Batman: Ark-M, Batman (cv91273), Batman: Bruce Wayne – The Road Home,
Batman: Life After Death, Berserk, Exquisite Corpses, Immortal Hulk, Moon Knight by Lemire &
Smallwood, The Nice House by the Sea, The Power Fantasy, Ultimate Universe.

## Unified comic library (mergerfs)

The separate "Requested Comics" Komga library was replaced with a **mergerfs union**: Mylar's
`comics/` and Omnibus's `comics_omnibus/library/` merge read-only into `comics_merged/`, which
is what Komga reads. Both tools' comics now appear in the existing publisher libraries while
each still writes only to its own branch.

Chosen over the alternatives after establishing that **Omnibus already uses Mylar's exact
`$Publisher/$Series ($Year)` layout** and that there were **zero collisions** between the two
trees. Rejected: hardlinks (stale-link lifecycle), and letting Omnibus write into `comics/`
with metadata off — that last one collapsed on inspection, because **Mylar cannot tag files it
did not download** (`enable_check_folder=False`, `imp_metadata=False`, and ComicTagger is not
even installed: `ModuleNotFoundError: comictaggerlib`). Nothing would have written ComicInfo.xml
at all.

Komga's internal path was kept identical so its library roots needed no edit — important
because the Homepage API key is guest-level and 403s on library changes.

**Requested Comics now holds 0 series** and can be deleted in the UI.
